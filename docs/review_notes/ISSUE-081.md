## Security Findings
_Source: reviewer-degraded_

- **[Critical] A blocking review gate is silently disarmed by author-writable local refs that are invisible in the PR**
  Evidence: See the AC-9.3 code finding for full reproductions. The security-relevant shape: `refs/remotes/origin/HEAD`, `refs/remotes/origin/main` and `refs/heads/*` are all purely local, author-writable, never pushed and invisible to a reviewer reading the PR on the forge. The cheapest disarm is ONE `git update-ref` in any repo whose trunk is not literally named `main` or `master`, and a zero-rewrite variant creates `refs/tags/main` + `refs/tags/origin/main` while leaving every trunk ref honest and untouched. In all cases the output is the ordinary `PASS: gate-evidence - no gate DETECTED in the diff.` at exit 0 -- byte-identical to a legitimately gate-free PR, with no `WARN:` line. This is the kit's own recorded pattern 'a control whose legitimate quiet output is identical to its defeated output must emit counter-evidence, not just an absence of warnings', recurring inside the control built to stop defeated controls.
  Fix: Resolve trunk candidates by full ref path and corroborate against `origin/HEAD`'s target ref rather than its stripped last component. Where corroboration is impossible (no remote, unknown trunk name), print the counter-evidence line rather than passing silently.

- **[Medium] A committed `.gitattributes` textconv driver still disarms the gate into a gate-free PASS, and is disclosed nowhere**
  Evidence: `.gitattributes` `*.py diff=hide` plus `git config diff.hide.textconv /usr/bin/true` produces a diff with no hunk and no `Binary files` marker: `diff --git a/scripts/guard.py b/scripts/guard.py` / `new file mode 100644` / `index 0000000..4f66541` and nothing else. Measured consumer verdict `True (exit 0)`, `PASS: gate-evidence - no gate DETECTED in the diff.` Neither layer covers it -- `--text` does not disable textconv, and layer 2 has no marker to see. It needs a local config line as well as the committed one (git never reads committed config), so it is outside AC-9.1's literal 'one committed line'; but it is reachable through any committed setup script, devcontainer `postCreateCommand` or `make init` that runs `git config`.
  Fix: Either pass `--no-textconv` at both render sites, or name this residual explicitly in AC-9.1 and in `_binary_rendered`'s docstring. Silence is the problem here, not the gap.
