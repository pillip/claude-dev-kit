- **[Critical] The gate is silently disarmed in full by author-writable local git state: a feature-branch `origin/HEAD` collapses the diff to empty, and an empty diff is read as "no gates"**
  Evidence: scripts/verify_checkpoint.py:1304-1309 + scripts/verify_gate_evidence.py:733. Chain: `_default_branch()` resolves from `refs/remotes/origin/HEAD` -> if it names the feature branch, `merge_base == HEAD` -> `git diff` exits 0 with EMPTY stdout -> `_gate_evidence_diff` returns `""` (not `None`) -> `analyze("")` finds no files -> `PASS: gate-evidence — no gate-adding change in the diff` -> exit 0. The output is byte-identical to a legitimately gate-free PR.
Proof (scratch repo, one unevidenced gate `check_payout_limit` committed on branch `work`):
  origin/HEAD before: (unset)
  BASELINE: FAIL: gate-evidence — 1 gate(s) added without paired evidence / EXIT = 1
  `git remote set-head origin work`  ->  origin/HEAD after: refs/remotes/origin/work
  ATTACK:   PASS: gate-evidence — no gate-adding change in the diff / EXIT = 0
`refs/remotes/origin/HEAD` is purely local, never pushed, and invisible in a PR — review lesson 5 verbatim (workspace-persisted state read by gates is untrusted input; validate on read). The same accident fires with no attacker at all when the branch under review IS the default branch.
  Fix: Fail CLOSED on both halves of the conflation: in `_gate_evidence_diff`, refuse when the resolved `diff_base` is `HEAD` (or when the resolved default branch is the branch under review), and return `None` rather than `""` for a zero-byte diff; in `verify_review_gate_evidence`, require a non-empty diff before trusting a PASS. `_default_branch()` is pre-existing and shared with `_changed_files_vs_base`, so weigh a module-wide fix against a local one.

- **[Critical] Quadratic regex backtracking in `_CONDITIONAL` hangs the blocking checkpoint on author-authored input — 40 s from a 7-line diff, with no timeout and no line-length bound**
  Evidence: scripts/verify_gate_evidence.py:98-100, alternative 3 `\bif\b.+\belse\b`. One added line inside a `def` in a non-test `.py` file, not beginning with if/elif/while/assert, containing many `if` and no `else`:
  diff bytes: 192151  lines: 7
  PASS: gate-evidence — no gate-adding change in the diff
  python3 --diff-file redos.diff  39.83s user 0.42s system 99% cpu 40.374 total
Scaling of `analyze()` on a single line: 24 KB -> 0.62 s, 48 KB -> 2.49 s, 96 KB -> 10.25 s, 192 KB -> 40.4 s. 4x length = 16x time, so ~1 MB line ~= 18 min and ~5 MB ~= 7.5 h. `_GIT_TIMEOUT = 30` guards only the subprocess; scripts/checkpoint.sh:21 `exec`s python3 with no wall-clock bound, and `analyze()` has no per-line length bound. Directly relevant to this sprint: three agents were already killed by a 600 s no-progress watchdog, so a hangable blocking gate is an availability defect against the kit's own runner, not a theoretical one.
Measured and cleared, no finding: `_VACUITY_RE` (:182), `_destring` (:249) and `_LITERAL_EXPECTED_RE` (:195) are all linear at 2k/4k/8k (<=0.005 s) — their alternations are disjoint.
  Fix: Bound per-line length before regexing (skip or flag lines over ~2 KB) and replace alternative 3 with a bounded quantifier `\bif\b[^\n]{0,400}?\belse\b` or a cheap `"if" in line and "else" in line` pre-check.
