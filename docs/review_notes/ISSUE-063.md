# Review Notes — PR #111

## Code Review
_Source: reviewer-degraded_

- **[Medium] HTML targets never get CSS comments blanked, so comment-interleaved flex-calc-width declarations in inline style attributes and <style> blocks still evade the sweep, contradicting the new docstring guarantee**
  Evidence: scripts/verify_design_sweeps.py:381-382 — `stripped = (strip_html_comments(raw) if kind == "html" else strip_css_comments(raw))`; the tell is registered for both kinds (line 304: `kinds=("html", "css")`), and the module docstring added by this diff (lines 22-25) claims a declaration split 'around a blanked comment' 'cannot evade the sweep'. Probe-confirmed: `<div style="width: /* cols */ calc(33% - 1rem)">` and `<style>.col { width: /* c */ calc(33% - 1rem); }</style>` in a screen file both exit 0 with zero flex-calc-width hits, while the identical declaration in styles.css exits 1 (control). Plain multi-line splits in HTML ARE caught, so the gap is comment-blanking only. Inline style attributes and <style> blocks are parsed as CSS by the browser oracle, where /* */ comments are legal inside a declaration.
  Fix: In run_ai_tell, feed the declaration-level scan on html targets through the CSS stripper too: compute `collapsed, line_of = collapse_ws_with_lines(strip_css_comments(stripped) if kind == "html" else stripped)` — scoping the extra blanking to the declaration-level pass keeps the line-wise tells' rendered-text semantics untouched. Alternatively (zero code): narrow the docstring claim to stylesheet contexts and record the HTML gap under ISSUE-064 (matcher-robustness owner). Either way, add a mutation pair for the chosen behavior. Pre-063 had the same blind spot but did not document the stronger claim.

- **[Low] `all --json` on a usage-error path prints a PARTIAL aggregate (missing the errored sweep's key) instead of either a complete document or no document**
  Evidence: scripts/verify_design_sweeps.py:514-523 — when run_literal_quote returns 2 (philosophy file missing) it never reaches _emit, but main() still prints `json.dumps(collect)`. Probe-confirmed: `all --class ... --json` with docs/design_philosophy.md deleted exits 2 with stdout JSON keyed only {ai-tell, signature-move}. Inconsistent with the other usage-error surface: `all --json` without --class emits NO JSON at all (stderr only). A consumer iterating the three sweep keys (the AC-2 shape) gets a KeyError on the exit-2 path.
  Fix: Make the exit-2 surface uniform: skip the aggregate print when a usage error occurred (`if collect is not None and 2 not in codes: print(...)`), matching the no-JSON-on-usage-error behavior of every other exit-2 path. Low because exit code 2 already gates machine consumers and no call sites are wired until ISSUE-057.

- **[Low] Documented exit-2 classification for `all` without --class is untested — both AC-3 tests accept rc in (1, 2)**
  Evidence: tests/test_sweep_contract_conformance.py:274 and :286 (`assert cp.returncode in (1, 2)`), tests/test_sweep_validators.py:401 (`assert rc in (1, 2)`), versus scripts/verify_design_sweeps.py:31-33 and 44-45 which pin the missing-class case as a usage error (exit 2). A regression reclassifying it as rc 1 (violations) would pass the whole suite while contradicting the module docstring and blurring the 0/1/2 distinction the ISSUE-057 checkpoint wiring will key on (misconfigured invocation vs design violations).
  Fix: Tighten the conformance tests to `assert cp.returncode == 2` (AC-3 only demands non-zero, so this is a strengthening, not a conflict). Keeping the SystemExit tolerance in test_sweep_validators.py is fine — argparse-based implementations also exit 2.

- **[Low] [record] Usage-error messages relocated stdout -> stderr on per-sweep CLIs — strictly a behavior change under AC-5's 'per-sweep CLI unchanged' wording**
  Evidence: Byte-level differential of pre-063 vs fixed script over 11 invocations: all pass/violation paths byte-identical on both streams (including `all --class` text and every per-sweep --json); the ONLY diffs are exit-2 paths, e.g. `signature-move` without --class and `ai-tell --exempt bogus` print the byte-identical message on stderr instead of stdout (scripts/verify_design_sweeps.py:125,216,352-357). Exit codes unchanged everywhere.
  Fix: No code change needed — the relocation is load-bearing for AC-2 (keeps `all --json` stdout a single document) and matches the majority family convention (verify_figma_compliance.py:920, verify_structural_match.py:364 use stderr; verify_hollow_tests.py:186,191 still uses stdout). Record the deviation in the PR/issue closeout so AC-5's 'unchanged/byte-identical' claim is scoped to exit-0/1 paths, and consider aligning verify_hollow_tests.py in a follow-up.

- **[Low] [record, pre-existing] strip_css_comments is string-blind: a /* ... */ pair split across two string literals wipes a real declaration between them, evading the new declaration-level scan**
  Evidence: Probe-confirmed on the fixed script: `content: "a /* b"; width: calc(33% - 1rem); content: "c */ d";` in styles.css exits 0 with zero flex-calc-width hits — the blanking regex (scripts/verify_design_sweeps.py:68, unchanged by this diff) spans from the /* inside the first string to the */ inside the second, erasing the width declaration a browser would apply. Review lesson: hand-rolled strippers mirroring the browser oracle must match string-literal edge cases in every swept language.
  Fix: Route to ISSUE-064 (detection-robustness owner): make the CSS stripper string-aware (skip over '...' / "..." spans when locating comment delimiters). Not a regression — the identical stripper fed the pre-063 line-wise scan — and the path is adversarial-only, hence Low.

## Security Findings
_Source: reviewer-degraded_

- **[Low] Quadratic (O(n^2)) scan time in declaration-level flex-calc-width sweep over whole-file collapsed text**
  Evidence: scripts/verify_design_sweeps.py:302 pattern `width\s*:\s*calc\(\s*[^)]*%` + :397-401 `tell.pattern.finditer(collapsed)`. Before this diff the pattern ran line-wise, bounding `[^)]*` to one line; collapse_ws_with_lines turns the whole file into one line, so each failed match scans to EOF. Probe (confirmed): CSS of k repeated unclosed `width:calc(` openers scales 4x time per 2x size — 500x/56KB=30ms, 1000x/113KB=121ms, 2000x/226KB=484ms, 4000x/452KB=1948ms; extrapolates to ~minutes at single-digit MB. Benign CSS (20k closed calc declarations, 880KB) stays at 11ms.
  Fix: Bound the open-declaration scan so a missing `)` cannot run to EOF: narrow the class to characters legal inside an unterminated declaration, e.g. `width\s*:\s*calc\(\s*[^);}{]*%` (`;`, `{`, `}` end/invalidate the declaration in practice), or cap it with `[^)]{0,256}`. Either keeps the multi-line detection intact and restores linear worst-case time.

- **[Low] Raw terminal escape sequences from swept files pass through to text-mode violation snippets (new declaration-level path replicates pre-existing line-wise pattern)**
  Evidence: scripts/verify_design_sweeps.py:408 `"snippet": source_lines[lineno - 1].strip()[:100]` (new in this diff) and :394 (pre-existing), printed raw at :416 `f"{v['file']}:{v['line']}: [{v['tell_id']}] {v['snippet']}"`. Probe (confirmed): a screen file containing ESC `]0;PWNED` BEL emits the raw 0x1b byte to stdout in text mode (od shows `033 ] 0 ; P W N E D \a`); an ANSI/OSC sequence in a swept file can retitle the terminal or cursor-rewrite the human-readable report (e.g. visually mask a FAIL line). JSON mode is safe — json.dumps ensure_ascii escapes it to \u001b. Exit codes are unaffected, so the machine gate cannot be spoofed.
  Fix: Sanitize snippets before embedding in text output: strip C0/C1 control characters except tab, e.g. `re.sub(r'[\x00-\x08\x0b-\x1f\x7f]', '', line).strip()[:100]` applied in both the line-wise and declaration-level hit builders (or in the single formatting site at the `lines +=` step).

- **[Low] `all --json` prints a partial, pass-looking aggregate document on a mid-run usage error (exit 2)**
  Evidence: scripts/verify_design_sweeps.py:124-126 (run_literal_quote returns 2 without _emit when the philosophy file is missing) + :514-523 (remaining sweeps still populate `collect`; `print(json.dumps(collect, indent=2))` runs unconditionally). Probe (confirmed): `all --class sig --json` against a tree without docs/design_philosophy.md exits 2 but prints a syntactically valid 2-key document in which both present sweeps are "status": "pass" and the literal-quote key is absent. A consumer that parses stdout and iterates over present keys without checking the exit code concludes all-pass — a fail-open hazard for the gate. The new conformance tests pin set(payload) == ALL_SWEEPS only on exit-0/exit-1 paths.
  Fix: On any usage-error (code 2) in `all --json`, either suppress the aggregate print entirely (stderr already carries the ERROR line) or emit an explicit error entry for the failed sweep (e.g. {"sweep": "literal-quote", "status": "error", ...}) so the document always contains all three keys; add a conformance test pinning the exit-2 stdout shape. (Overlaps the code dimension's contract-shape concern; flagged here for the fail-open angle.)
