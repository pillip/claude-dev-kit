## Security Findings
_Source: degraded: reviewer agent (decide -> path=degraded, reason=context-unreachable); npm script-string route re-measured independently by the team-lead_

- **[Low] A symlinked or directory-shaped scoped path would expand the executed set; it is blocked only incidentally**
  Evidence: `_existing` uses `.exists()`, which follows symlinks, and the `./` prefix now makes such a path unambiguously a directory for pytest to recurse into. Measured: a directory named `tests/test_link.py` gives `exists()=True is_dir()=True`, and had it reached pytest it would have run `tests/test_link.py/test_many.py::test_a` and `::test_b`. The gate is safe today only because `read_text()` on a directory raises `IsADirectoryError`, which `except OSError: return False` catches and the hollow-test check treats as 'shallow'. Nothing records that as load-bearing; the inventory discusses path SHAPE and never path TYPE. If `_has_real_tests` ever softens an unreadable path to 'unknown -> allow', this becomes a real scope-expansion bypass. Carrier.

- **[Low] Non-ASCII test filenames are silently dropped and produce a false `no test files found` diagnostic**
  Evidence: git C-quotes non-ASCII and control-character paths by default, so `tests/test_uni_\303\244\344\270\255.py` arrives quoted and `_existing` drops it as non-existent. If such a file is the branch's only test, the gate prints `FAIL: no test files found — write tests before RED phase`, which is false. Fail-closed and pre-existing (`_existing` dates to ISSUE-048, unchanged here). Raised because the SAME C-quoting is what makes the newline/ESC output-forgery vector unreachable — one mechanism, two opposite consequences, neither documented. Carrier.

- **[Low] Command injection via crafted filenames: ruled OUT by measurement on both legs, recorded so the negative is not re-derived**
  Evidence: `grep -n "shell=True" scripts/verify_checkpoint.py` -> zero matches; the single seam `_run` passes a list with only `cwd=`/`timeout=`. Real npm probe, 13 payloads x 2 script shapes (including a `bash -c` script so shell-level word splitting would be visible): every metacharacter arrived as ONE literal argv element (`ARG4=[tests/a$(touch INJECTED_CMDSUB)x.test.js]`, backtick, `;`, `|` likewise) and zero `INJECTED_*` side-effect files were created. Control characters are C-quoted by git regardless of `core.quotePath`, so newline/ESC cannot reach argv or gate output. ReDoS: measured linear at three scales (n=100k/400k/1.6M -> 0.0024/0.0096/0.0382s). `{base}` in the new UNVERIFIED line comes only from `git symbolic-ref` or the literals `main`/`master` and is not controlled by the gated party.
