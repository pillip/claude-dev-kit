- **[High] Detector missed 11 renderings of the field line, re-opening autonomous dispatch while reporting the field as absent**
  Evidence: `_WATERMARK_FIELD_RE` enumerated only `[-*]` as bullet markers and only `[ \t]` as whitespace. CommonMark has three bullet markers. A missed line sets `watermark_present=False`, which (a) re-opens the above-boundary dispatch gate and (b) takes the `elif unrostered_ids:` branch, so the engine AFFIRMATIVELY reports `[roster-watermark: absent from ## Meta]` about a field that is plainly in the file. Reproduced on the Harm B fixture: flipping one byte (`-` -> `+`) turned `action=DONE, targets=[]` into `action=PIPELINE, targets=['ISSUE-070','ISSUE-071','ISSUE-072']`. Same for NBSP/ZWSP indentation, `_emph_`, `~~strike~~`, `***triple***`, `> ` blockquote. The duplicate guard inherited the hole: a canonical field plus a `+`-bulleted second copy counted as ONE hit and silently honoured the first -- the exact loosening the duplicate rule exists to stop.
  Fix: FIXED in review. Detector folded into one character class covering the full marker/whitespace/emphasis alphabet. 21 renderings now detected, 8 prose/row negative controls still not detected. All 15 layout variants are found-then-refused (gate closed, announced). Mutation M-A (revert the alphabet) kills 22 tests.

- **[High] Quadratic backtracking in the detector could wedge the autonomous sprint loop indefinitely**
  Evidence: The old pattern had two adjacent greedy `[ \t]*` runs separated by an optional atom, applied per line to a file the module itself designates untrusted. Measured: 20k spaces 4.0s, 80k 66.3s, ~1MB ~3 hours. `next-action` runs at step 4b of every sprint iteration with no timeout wrapper, so one padded line stalls the loop with no JSON on stdout and no diagnostic. A hang is strictly worse than an exception here because nothing catches it. Pure regression: main has no such pattern.
  Fix: FIXED by the same character-class rewrite (no adjacent quantifiers). 2,000,000 chars in 0.014s. Pinned by `test_detection_is_linear_not_quadratic` (parametrized on space/tab) and `test_detection_is_linear_on_a_near_miss_line`. The probe size is deliberately 20k, not 500k, so reverting the fix FAILS the test in ~11s instead of hanging it.

## Security Findings
_Source: reviewer-degraded_

- **[High] A single byte in workspace-writable state flips the engine from restraint to autonomous dispatch, with a falsified audit line**
  Evidence: Threat: every phase executor rewrites `docs/sprint_state.md` on every iteration -- that is the feature's premise. Changing the field's bullet from `-` to `+` (one differing byte, confirmed with `cmp -l`) takes `DONE`/`targets: []` to `PIPELINE`/`['ISSUE-070','ISSUE-071','ISSUE-072']`, i.e. three out-of-scope Board issues enter autonomous implement -> review -> merge. Output becomes byte-identical to the field-deleted file. 11 of 21 field-shaped lines were missed this way (NBSP/ZWSP indent, `_`/`__`/`~~`/`***` emphasis, `> ` blockquote). The engine does not merely stay quiet -- it asserts `[roster-watermark: absent from ## Meta]` about a visible field. `scripts/sprint_queue.py` is the only reader of the field, so there is no second line of defence. The test-local oracle mirrored the implementation's `[-*]`, so implement-phase mutation testing structurally could not diverge from the bug (review lesson 4).
  Fix: FIXED (see the Code Review High of the same name). The test oracle `_FIELD_LINE_RE` was additionally re-pointed at the markdown grammar (`[-+*]`) rather than the implementation, with `test_the_test_oracle_covers_the_grammar_not_the_implementation` pinning all three markers, so the oracle can diverge from the code in future.

- **[High] ReDoS in the detector hangs the sprint loop's decision engine with no diagnostic**
  Evidence: Same writer as above. `_WATERMARK_FIELD_RE.match` ran on every line of `sprint_text` with clean O(n^2) behaviour on whitespace-only lines. A 200 KB file with one 200,000-space line: branch exits 124 after 45s of CPU with no output; main returns in 0.03s. Measured scaling 10k->1.0s, 20k->4.0s, 40k->16.1s, 80k->66.3s. The sprint skill invokes `next-action` bare at step 4b with no timeout wrapper, so this stalls the autonomous loop rather than failing it -- and a stall is not caught by any wrapper, unlike an exception.
  Fix: FIXED by the character-class rewrite: 4,000,000 chars in 0.028s. Two timing pins added, deliberately sized so the regression is observable as a failure rather than a hang.

- **[Medium] Unicode line separators smuggled an honoured boundary past every line-based reader**
  Evidence: `str.splitlines()` also splits on VT, FF, FS, GS, RS, NEL, U+2028 and U+2029, none of which `Path.read_text`'s universal-newline translation normalizes. So a physical newline-delimited line could contain a field declaration -- or a whole `## Meta` heading -- that only this parser could see. Reproduced: a file whose `- Started:` line carries `U+2028- Roster-Watermark: ISSUE-075` returns `grep -c '^- Roster-Watermark:'` = 0, yet the engine honoured and announced a boundary of ISSUE-075, silencing all 5 issues the same file otherwise reports. All eight separators work.
  Fix: FIXED: detection deliberately keeps `splitlines()` so the smuggled field IS found (which closes the dispatch gate), and acceptance then refuses it -- a document whose line structure is ambiguous does not get to pin the boundary. Named reason: "document contains a non-newline Unicode line separator, so a field line here is not visible to a line-based reader". Matrix variant `smuggled_behind_u2028`; mutation M-F kills it.

- **[Medium] The range-sanity ceiling was forgeable from `issues.md`, and had no floor**
  Evidence: See the Code Review Medium "ceiling was derived from attacker-controlled Board data" and Low "no floor". The operator who exports `KIT_SPRINT_DISPATCH_ABOVE_WATERMARK` consents to "dispatch issues registered above my boundary"; with a forged boundary of 0 that becomes "dispatch the whole Board", including pre-existing debt deliberately deferred at planning. Default-off keeps it out of `targets`, which is why this is Medium rather than High.
  Fix: FIXED: ceiling clamped to 9999, floor at 1, and the accepted-pin note now carries `X of Y Board backlog issue(s) are above it` so a defeated control is legible rather than inferable.

- **[Medium] Untrusted Board ids were echoed unbounded into the LLM-facing verdict string**
  Evidence: See the Code Review Medium on Note C: 259,734 chars of `reason` from 60 rows carrying one 4299-digit dep id, versus 91 chars on main. `reason` is the channel the sprint skill and `team-lead` read as the engine's verdict, so burying `action`, `targets` and the `[dispatch: ... NOT dispatched]` restraint marker under a quarter megabyte of digits is a practical way to make the orchestrator misread it.
  Fix: FIXED: truncated per id and capped at 5 gaps with `and N more`; pinned at `len(reason) < 2000`.

- **[Low] The 40-char echo window was wide enough to forge the engine's own bracketed sentinels**
  Evidence: The one rejection branch that echoes untrusted text truncated and `!r`-escaped it, which already neutralized ANSI, RTL override, NUL and JSON-breaking content (all verified refuted). The residue was semantic: 40 characters fits a convincing lookalike of the engine's own markers, e.g. a value of `x] [dispatch: ENABLED] [ok` landing verbatim beside the real `[roster-watermark: ...]` note. Review lesson 10: those sentinels are data, not directives -- so the untrusted echo must not be able to spell one.
  Fix: FIXED: `_truncate_value` strips `[` and `]` before capping. The value is still echoed (minus brackets) so an operator can see what was refused. Pinned by `test_the_echoed_value_cannot_spell_the_engines_own_sentinels`; mutation M-C kills it.

- **[Low] Negative space: the attacks that FAILED, so the covered ground is explicit**
  Evidence: Refuted, each executed rather than reasoned about. "Never raises" could not be refuted: a sweep of all 1,114,112 codepoints found none that match `\d` and make `int()` raise, and the CPython 4300-digit str-to-int crash is genuinely closed on every reachable `int()`, including the Board scan (a 4301-digit Board heading yields valid JSON and does NOT disable the control -- the other ids are still reported, so the GAP-068h shape is correctly closed for that input). Env knob: every non-ASCII codepoint substituted at every position of all four truthy words gave 0 lookalike acceptances; `0`, `false`, empty, garbage and shell-metacharacter payloads all leave dispatch OFF; `.lower()` rather than `.casefold()` is the safer choice and was kept. Id-mismatch widening refuted: `unrostered_ids`, the synthesized row's `issue` cell and the `implement_ready` entry are the same string object by construction, so the withholding filter cannot miss an id; synthesized rows are hardcoded `phase: "backlog"` so nothing leaks into `ship_ready`/`review_ready`. `## Meta` structural forgery (no heading, `##Meta`, `### Meta`, setext, sibling `## Notes`, a second `## Meta`) all fail closed and announce. CRLF and lone-CR endings are correctly normalized. No command injection, path traversal, secret, deserialization or new-dependency surface in the diff.
  Fix: No action required -- recorded so the negative space is auditable.
