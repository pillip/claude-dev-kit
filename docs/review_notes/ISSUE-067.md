## Security Findings
_Source: reviewer-degraded_

- **[High] `--project-path` renders the containment control vacuous; new arbitrary multi-level directory-creation + JSONL-append primitive outside any project**
  Evidence: Anchors `scripts/kit_telemetry.py:139` (`project = Path(project_path) …`), `:145` (containment compare), `:151` (`runs_dir.mkdir(parents=True, exist_ok=True)`), `:216-218` (`--project-path` CLI arg, no validation). The containment check compares `runs_dir.resolve()` against `project.resolve()` — both derived from the same attacker-supplied value — so it can never fail for a non-symlinked root: "containment relative to the supplied project root" is not a control when the attacker supplies the root. Proven: EXP7 wrote `victim_home/.claude/runs/unattributed.jsonl`; EXP7b created a brand-new four-level tree plus `.claude/runs/` and the event file; EXP8 showed `..` normalized by `resolve()` so the write escapes the nominal subtree; EXP9 followed a symlinked root; EXP10 wrote relative to the caller's cwd. Regression, not pre-existing: main gated on `if not runs_dir.is_dir(): return` (`scripts/synthesize_gate_results.py:403` on main), so a non-kit directory was a no-op (EXP13: `MAIN created .claude? False`). Corroborated in-repo by the PR's own test diff, which had to repoint `/tmp/fake` → `tmp_path` in nine `TestRunVerifyGates` cases with the stated reason "a shared literal path would leak writes onto the host filesystem" (`tests/test_verify_checkpoint.py:1177-1182`). High rather than Medium because the skills grant `Bash(python3 scripts/kit_telemetry.py *)` / `Bash(python3 scripts/*)` — narrow grants to run kit scripts, not arbitrary Python — and this CLI converts that into "create directories and append JSON anywhere the user can write". Not Critical: the primitive is append-only, the filename is fixed (`<validated-run-id>.jsonl`) and the content is well-formed JSON.
  Fix: PARTIALLY FIXED in review. The reviewer's proposed fix (refuse when `<project>/.claude` is absent) directly contradicts AC-1/TC-067b, which pin `.claude/runs/` auto-creation, so only the AC-preserving portion was applied: `emit_event` now refuses with an announcement when the project ROOT is not an existing directory (`scripts/kit_telemetry.py`), killing the multi-level creation primitive. Verified live — the reviewer's EXP7b now prints `skipped: project root '…' is not an existing directory; event 'y' NOT written` and creates nothing, while auto-creation inside an existing root still works. Pinned both directions by `test_absent_project_root_is_refused_not_created` and `test_absent_project_root_refused_through_the_cli`. RESIDUAL (unfixed, still High) — the reviewer re-tested the in-flight fix and confirms it does NOT close F1 (EXP18): any *existing* writable directory (`~`, `~/.ssh`) is still written, so only the non-existent-path case is blocked. Closing it fully requires choosing between AC-1's "auto-create, never skip" and ISSUE-058's "only write inside the kit project" — a scope decision for the issue owner, not a review fix. Needs a follow-up issue.

- **[Medium] FIFO (or blocking device node) at the now-predictable event path hangs the emitter forever, breaking the "never fail the parent" contract**
  Evidence: `scripts/kit_telemetry.py:180-184` — `os.open(..., O_APPEND | O_CREAT | O_WRONLY | O_NOFOLLOW)` with no `O_NONBLOCK` and no post-open `fstat`. A pre-planted FIFO at the (now fixed and predictable) `unattributed.jsonl` path blocks `os.open` until a reader appears; `O_NOFOLLOW` does not refuse FIFOs, there is no `O_NONBLOCK`, and `except OSError` cannot catch a block. Reproduced: EXP5 reached the harness timeout (exit 124), where main's emitter returned immediately (EXP13). So the "never fail the parent" contract is violated by HANGING the gate checkpoint — and unlike a raise, a hang is not caught by the `except Exception` wrapper at `scripts/verify_checkpoint.py:906-926`. Workspace state is untrusted input (review lesson 5), so planting a FIFO under `.claude/runs/` is in the threat model. DoS only — no integrity or confidentiality impact — hence Medium.
  Fix: Add `os.O_NONBLOCK` to the flags and verify the opened object is a regular file via `os.fstat` before writing, announcing a named refusal otherwise. No FIFO, hardlink, device-node, TOCTOU, U+2028 or announcement-injection test exists anywhere in `tests/`.

- **[Medium] Pre-planted hardlink at the event path defeats both containment and `O_NOFOLLOW` — now reachable at a fixed filename**
  Evidence: `scripts/kit_telemetry.py:180-184` (same open call as the FIFO finding). A hardlink is indistinguishable from the real file to both the containment check and `O_NOFOLLOW`, so an attacker-planted hardlink at `.claude/runs/unattributed.jsonl` receives the appends. Honestly scoped by the reviewer: the open call is byte-identical to main's, so the control gap is pre-existing — what this PR changes is reachability, because the target filename is now fixed and written on every default-configured run instead of requiring a known `KIT_RUN_ID`. Impact ceiling is append-only corruption of an attacker-chosen file.
  Fix: The `fstat` from the FIFO fix plus a link-count refusal (`st_nlink > 1` → announce and skip).

- **[Medium] `resolve()` → `mkdir` → `open` TOCTOU — containment bypass reproduced**
  Evidence: `scripts/kit_telemetry.py:145` (check), `:151` (mkdir), `:181` (open) operate on path strings re-resolved at each step, so an attacker who can swap `.claude` or `.claude/runs` for a symlink between the check and the open bypasses containment. Escape ACHIEVED on attempt 5 (EXP15c). Two supporting proofs: `mkdir(exist_ok=True)` silently accepts a symlink-to-dir (EXP15a), and `O_NOFOLLOW` writes straight through a symlinked *directory* component because it only guards the final path component (EXP15b) — so the containment check is the sole barrier, and it is time-of-check. Distinct from the ordering finding in the Code Review section: the ordering is correct (and now pinned), but ordering alone is insufficient. The reviewer flags its "273 attempts on main" comparison as carrying a harness caveat.
  Fix: Resolve once and operate on directory file descriptors (`os.open(dir, O_DIRECTORY)` + `os.open(name, ..., dir_fd=...)`), which makes the checked object and the written object the same object.

- **[Medium] Announcements interpolate unvalidated, unbounded, unescaped strings into stdout — the kit's designated *only* skip signal**
  Evidence: `scripts/kit_telemetry.py:103-105` (`_announce` → bare `print`). (a) Newline injection in `event_type` forges a clean-path announcement (EXP12a). (b) Terminal-escape injection passes through unescaped — `\x1b[2K\x1b[1A\x1b[31m…` can erase and rewrite preceding transcript lines (EXP12b). (c) `event_type` is bounded nowhere: a 5000-char `--event` is printed in full (EXP12c), while the event BODY truncates only `payload["detail"]` to 512 chars. Honestly scoped by the reviewer: no machine consumer parses this stdout (`scripts/checkpoint.sh` only `exec`s `verify_checkpoint.py`; the `GATES DELEGATED` marker is read by humans), so the impact is operator-transcript integrity — but this stdout line is by design the ONLY signal on the containment-rejection path, so forging or erasing it defeats the issue's core guarantee.
  Fix: Sanitize and bound inside `_announce` (strip control characters, cap length) and clamp `event_type` at the API boundary.

- **[Medium] `ensure_ascii=False` emits raw U+2028 / U+2029 / U+0085, silently destroying the record for the documented `splitlines()`-based consumer**
  Evidence: `scripts/kit_telemetry.py:169` — `json.dumps(event, ensure_ascii=False)` leaves U+2028, U+2029 and U+0085 as raw characters, which Python's `str.splitlines()` treats as line breaks. A payload containing one of them splits a single event into two unparseable lines for a `read_text().splitlines()` reader (the shape `scripts/trace_query.py:46` uses). Proven end-to-end (EXP11): `trace_query.load_events()` parsed **0 events** from a valid written record and swallowed the loss through its own "tolerate a torn line" branch — the silent skip, relocated from the writer to the consumer, which is exactly the class this issue exists to eliminate. Honest scoping from the reviewer: forgery is NOT possible (EXP14, 5 shapes tried), the in-repo producers are safe (all 20 error sites use `!r`), `trace_query.py` does not read this sink on its default path, and `ensure_ascii=False` is carried over from main — so this is latent corruption reachable only via attacker-supplied payload text, not a live break.
  Fix: Escape the three separators at serialization (all three sit inside the one `json.dumps` call at `:169`), or drop `ensure_ascii=False`.

- **[Low] The shared `unattributed.jsonl` sink is unrotated, uncapped, world-readable, and now written on every default-configured run**
  Evidence: `scripts/kit_telemetry.py:86` (`FALLBACK_RUN_ID = "unattributed"`) plus the `0o644` mode at the `os.open` call. Checked and clean by the reviewer: this is NOT a commit leak — `.gitignore:7-8` covers `.claude/run/` and `.claude/runs/` in this repo. Residual impact is unbounded local disk growth plus long-lived world-readable event content (EXP17b/EXP17c).
  Fix: Open with `0o600`, and refuse-with-announcement when the sink exceeds a documented size ceiling.

- **[Low] Broad `except Exception` echoes absolute filesystem paths to stdout and reduces permission errors to one non-blocking line**
  Evidence: `scripts/kit_telemetry.py:189-193` (`except OSError`) and the outer `except Exception`. With `.claude/runs` a regular file the announcement echoes the full absolute path (EXP6). The reviewer notes the swallow itself is the intended contract (`:48-50`) — the finding is the path echo and the loss of a permission error's signal, not the non-blocking behavior.
  Fix: Announce the reason *class* rather than `str(exc)`, so the line names the failure without echoing absolute paths.

- **[Low] No `kit_telemetry` grant in the brainstorm/bizanalysis `allowed-tools` at HEAD — the kit's own allowed-tools lesson firing, re-creating the silent skip**
  Evidence: `skills/brainstorm/SKILL.md:6` and `skills/bizanalysis/SKILL.md:6` at commit eeb3de7 carry no `kit_telemetry` grant despite the PR adding 4 call sites in those two skills. Scored Low by the security reviewer because it fails CLOSED (the emit is denied, nothing unsafe runs) — but the consequence is that the migrated emit does not happen, which re-creates the very silent skip ISSUE-067 exists to remove.   Fix: FIXED in review — same fix as the corresponding High in the Code Review section: `Bash(python3 scripts/kit_telemetry.py *)` added to both `.tmpl` frontmatters and regenerated. Carried here separately because the two reviewers reached it independently from different angles (grant-escalation vs. fail-closed).
