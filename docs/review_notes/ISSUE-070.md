## Code Review
_Source: code-review_

- **[Medium] [FIXED] The `_quote` announcement hardening was applied at ONE call site; `--event` still forged a second `[kit-telemetry]` line on three other paths**
  Evidence: scripts/kit_telemetry.py. `_quote()` (repr-rendering of attacker text, the PR's one no-AC addition) wrapped `project_path` but not `event_type` on the 4096-byte-cap announcement, the KIT_RUN_ID fallback announcement, the outer-handler announcement, or either `main()` `--payload` announcement. Reviewer-executed through the real CLI consumer at the pinned head with `--event $'benign_event\n[kit-telemetry] fallback: all clear — nothing to see here'`: all three reachable shapes printed **2 lines** with a forged second `[kit-telemetry]` line that reads like an all-clear, exit 0. The `_quote`-protected containment path printed 1. Exactly review lesson 16 — a defence exercised in the arm direction at one call site and absent at the others. Independently flagged by the minimality axis and by runtime /code-review.
  Fix: FIXED in review: `_quote` applied at every announcement site that interpolates caller-supplied text. Re-ran the probe — all five paths now print exactly 1 line with the newline escaped as `\n`. Pinned by a parametrized `TestAnnouncementIntegrityEveryPath` over the three shapes plus an ordinary-event-name disarm case. Mutation-verified in two parts because `main()`'s f-strings wrap across lines and a single textual mutant silently missed them (KILLED 2 + 1). `{exc}` interpolations were examined and left alone: CPython renders `OSError.__str__` filenames with `%R`, so no attacker newline reaches stdout through a reachable exception type.

- **[Medium] [FIXED] Malformed bytes in untrusted `.git`/`commondir` content escape `_main_repo_root` and disable ALL telemetry in that tree**
  Evidence: scripts/kit_telemetry.py. `commondir.read_text(encoding="utf-8")` had no `errors=` (unlike its sibling `dot_git.read_text(..., errors="replace")`), and the surrounding `except OSError` does not catch `UnicodeDecodeError`. A NUL inside the commondir CONTENT reaches `Path.resolve()`, which raises `ValueError` — also not an `OSError`. Either escapes `_main_repo_root` into `emit_event`'s outer handler, so every emit in that tree becomes `[kit-telemetry] skipped: emit failed (...)`. A total outage of a best-effort instrument from one corrupt byte of workspace state — the same untrusted-on-read class as the Critical above. Raised by runtime /code-review (F4); reviewer confirmed the `ValueError` leg is reachable (`Path.is_file()` swallows a NUL in the gitdir path, but `resolve()` does not swallow one in the commondir content).
  Fix: FIXED in review: the whole `.git`-file branch is now one `try` with `except (OSError, ValueError)` falling through to the conservative answer, and `errors="replace"` on the commondir read. Pinned by `test_malformed_git_file_bytes_fall_back_instead_of_escaping` over three byte shapes. Honest note: the `ValueError` half SURVIVED its first mutation run — the guard was unpinned until the NUL-in-commondir case was added.

- **[Low] [CARRIED — GAP-070f] `_containment_root()` calls `Path.cwd()` unconditionally, so a deleted CWD fails every emit even when the caller passed a valid explicit `project_path`**
  Evidence: scripts/kit_telemetry.py:_containment_root. Pre-ISSUE-070 the emitter only touched the CWD for the `project_path=None` default. Runtime /code-review measured: with the CWD removed under the process, `emit_event(..., project_path='<valid repo>')` returns False with `skipped: emit failed ([Errno 2] No such file or directory)` where it previously wrote. Reachable from a long-lived gate process whose worktree `scripts/worktree.sh remove` deleted mid-run.
  Fix: Not fixed in review — it changes fallback semantics (which root wins when the CWD is gone), which is a scope decision rather than a minimal fix. Guard `Path.cwd()` with a try and fall through to `CLAUDE_PROJECT_DIR`. Recorded as GAP-070f.

- **[Low] [CARRIED — GAP-070g] `_main_repo_root` ignores GIT_DIR/GIT_WORK_TREE, diverging from the oracle it claims to mirror; the two oracle-agreement tests ERROR rather than fail in such a shell**
  Evidence: scripts/kit_telemetry.py:_main_repo_root documents itself as mirroring `bash scripts/worktree.sh root`. Reviewer-executed with `GIT_WORK_TREE`/`GIT_DIR` exported: the Python derivation correctly ignored them and stayed on the repo root, while the oracle returned `rc=128, fatal: not a git repository`. The divergence is in the narrowing (safe) direction, so it is not a security finding — but `TestContainmentRootDerivation._oracle` asserts `returncode == 0`, so both oracle-agreement tests would ERROR for any developer with those variables exported. `tests/conftest.py` carries no hermetic `delenv` for `GIT_*`, and per GAP-083a the `tests-written` gate makes adding one there awkward.
  Fix: Not fixed — environment-dependent test hermeticity, no user-visible behaviour. Record the divergence in the docstring (done) and add a `GIT_*` delenv to the test module when GAP-083a is resolved. Recorded as GAP-070g.

- **[Low] [FIXED] README overstated the worktree rule as unconditional**
  Evidence: README.md stated "Linked worktrees resolve to the MAIN repo root, so `<repo>/.worktrees/<branch>` and the repo root admit each other" with no qualification. After the containment-anchor fix that holds only for an in-tree worktree of a non-bare repo; an out-of-tree `git worktree add` target or a bare-repo-backed worktree now resolves to itself. This is a user-facing claim about a security boundary, raised by runtime /code-review (F6).
  Fix: FIXED in review: the README sentence now names both cases and says why (the emitter will not widen its own boundary on the strength of a `.git` file). The corresponding divergence from the `worktree.sh root` oracle is recorded in the `_main_repo_root` docstring.

- **[Low] [RECORDED] `CLAUDE_PROJECT_DIR` fully determines the containment root when the process is not inside a git work tree**
  Evidence: scripts/kit_telemetry.py:_containment_root step 2. Reviewer-executed: from a non-git CWD with `CLAUDE_PROJECT_DIR=<victim-home>`, the root became `<victim-home>` and `emit_event(project_path=<victim-home>/.ssh)` wrote `<victim-home>/.ssh/.claude/runs/atk.jsonl`. From inside a git work tree the knob is correctly ignored (git wins), which is the kit's own situation and is pinned by `test_git_work_tree_wins_over_the_env_knob`. Recorded rather than filed: this is the documented fallback working as designed, the knob is set by the Claude Code runtime rather than by caller data, and it is documented in both the module docstring and README per review lesson 2.

## Security Findings
_Source: security-review_

- **[Critical] [FIXED] Containment root is derived from unvalidated workspace content — a planted or overwritten `.git` file moves the write boundary to an arbitrary directory, re-opening AC-1**
  Evidence: scripts/kit_telemetry.py:_main_repo_root. The function reads a linked worktree's `.git` file (`gitdir: <path>`) and then that gitdir's `commondir`, and returns `commondir.resolve().parent` as the containment ROOT — with no validation. Both files are ordinary writable workspace content, reachable with the Write tool alone, at exactly the privilege level AC-2 already assumes (an attacker who can plant a FIFO at the event path). Reviewer-executed against the pinned head 8626f8c in a mktemp sandbox with a REAL `git worktree add` tree: rewriting `<wt>/.git` to `gitdir: <tmp>/fake` and `<tmp>/fake/commondir` to `<victim>/.git` gave `_containment_root() -> <victim>`, and `emit_event(project_path=<victim>/.ssh)` returned True, creating `<victim>/.ssh/.claude/runs/atk.jsonl` — the ISSUE-067 review's `~/.ssh` demonstration restored verbatim, with no `[kit-telemetry]` line printed. A second shape needs no overwrite at all: a NEW subdirectory inside the repo carrying a crafted `.git` file does the same. Raised independently by runtime /security-review (Vuln 1, confidence 10) and runtime /code-review (F1). A first review fix that asserted only `candidate.is_relative_to(hop)` was INSUFFICIENT and both runtime reviewers caught it: every ANCESTOR hop satisfies that predicate, and ancestors are exactly what an attacker wants. Reviewer re-verified: `commondir` = `<tmp_path>/.git` gave root `<tmp_path>` and a successful write into the victim; `commondir` = `/x` gave root `/`, making containment entirely vacuous.
  Fix: FIXED in review. `_main_repo_root` now anchors the hop to something the attacker cannot forge without already holding write access at the destination: the derived root must be a real work tree whose `.git` IS the common dir just followed (`common_dir.is_dir()` and `(hop / '.git').resolve() == common_dir`), with the ancestor containment check retained as a second leg. Verified by re-running both attack probes: all four hop shapes (sibling, ancestor, filesystem-root, bare-repo-parent) now fall back to the work tree, nothing is written, and the victim tree is byte-identical before and after. Pinned by a parametrized `test_a_hijacked_commondir_cannot_move_the_root` over all four shapes, with `test_a_genuine_commondir_hop_is_still_followed` as the disarm direction. Mutation-verified both ways: removing the anchor is KILLED (3), rejecting every hop is KILLED (9).

- **[Medium] [CARRIED — GAP-070e] The `fstat` guard does not close the TOCTOU window for LOCATION; a `.claude/` directory-symlink swap still escapes containment**
  Evidence: scripts/kit_telemetry.py. The module docstring claimed the post-open `fstat` is "the one that closes the TOCTOU window". It is not: `fstat` answers what KIND of file the descriptor is, never WHERE it is, and `O_NOFOLLOW` binds only the FINAL path component. Reviewer-executed through the same `datetime.now()` seam the PR's own TOCTOU test uses — after the containment check and the runs-dir mkdir have both passed, replacing `<project>/.claude` with a symlink to an outside directory makes `os.open` follow it. Result: plant fired True, `emit_event` returned **True**, and `<outside>/runs/toc.jsonl` was created outside the containment root with a well-formed event in it. Requires write access inside the project plus winning the race, i.e. strictly harder than the Critical above but the same attacker.
  Fix: Docstring corrected in review so the claim matches the code (ISSUE-075 is instructed to adopt this contract, so an overclaim here has a named downstream consumer). The defect itself is NOT closed: closing the location leg needs an `openat`/`dir_fd` walk over the directory components, which is well past a minimal review fix. Recorded as GAP-070e in docs/test_plan.md; needs a durable carrier.
