# Review Notes — PR #143

## Code Review
_Source: code-review_

- **[Medium] AC-4 substance gap: the two ends share the LAYOUT constant but not the ROOT, so worktree-emitted streams stay unread**
  Evidence: kit_telemetry.emit_event defaults project_path=Path.cwd(); trace_query.default_trace_paths defaults root=Path('.'). Neither hops to the git root. Verified in the REAL repo: three .claude/runs/ dirs exist (main root + .worktrees/issue-ISSUE-071-run-id-producer + .worktrees/issue-ISSUE-081-gate-evidence), and `python3 scripts/trace_query.py summary` from the main root reads only one of them -- the ISSUE-071 worktree's 2795-byte unattributed.jsonl is invisible. Reproduced minimally: emitting with CWD=<repo>/pkg/sub writes pkg/sub/.claude/runs/unattributed.jsonl, and `trace_query summary` from the repo root exits 1 with 'no events found'. The AC-4 test passes `project` explicitly to BOTH ends, so it pins the layout and never exercises root resolution. Since the kit runs gates inside worktrees, most emitted events remain effectively write-only -- the condition AC-4 exists to end.
  Fix: Resolve the read root the way the emitter resolves its containment root (kit_telemetry._containment_root / _main_repo_root), or have default_trace_paths walk up to the git root and glob every .claude/runs under it. Then extend the AC-4 test to a fixture where the emit CWD and the query CWD differ.

- **[Medium] Stale doc sites in the direct caller: scripts/synthesize_gate_results.py still promises the removed stdout line in three places**
  Evidence: synthesize_gate_results.py:71-77 (its own 'Env knobs (documented here and in README's environment-variable list)' block) states: 'unset or invalid => the event is written under the `unattributed` fallback run id with one `[kit-telemetry]` stdout announcement naming the knob -- no longer a silent no-op.' That is now false for the unset case. Also :392 'an unconfigured KIT_RUN_ID falls back to the announced unattributed run id' and :424 'The shared emitter (ISSUE-067) may additionally print its own [kit-telemetry] fallback announcement when telemetry is unconfigured (KIT_RUN_ID unset/invalid)'. This module IS the gate call site whose stdout contract the PR changed -- its own tests were edited in this same PR to assert empty stdout. TestIssue071KnobDocumentation checks only kt.__doc__ and README, so nothing catches it.
  Fix: Update the three sentences to the shipped split (unset = body-only and silent; invalid = one stdout line naming the knob). Note the owning-module and user-facing doc obligations in the AC are satisfied; this is the caller's own docstring.

- **[Low] RUNS_SUBDIR's 'this is the SINGLE home of that path' comment is false -- review_context.py is a live producer that still re-types the literal**
  Evidence: kit_telemetry.py:153-158 claims single-home status, but scripts/review_context.py:208 has `runs_dir = Path(project_path) / ".claude" / "runs"` and writes `runs_dir / f"{run_id}.jsonl"` at :230. The identity pin (trace_query.DEFAULT_RUNS_DIR is kt.RUNS_SUBDIR) therefore covers two of three ends: moving RUNS_SUBDIR would orphan review_context's events with the suite green. Verified by MUT-E in review -- moving the constant moved the emitter and the consumer together, and review_context not at all.
  Fix: Either soften the comment to name the pending third end, or (preferably) let ISSUE-075 -- already scheduled to migrate review_context.py onto the shared emit seam -- carry it. A durable carrier already exists, hence Low.

- **[Low] The 'trace not found' diagnostic is now dead on the default path**
  Evidence: trace_query.py main(): `paths = args.traces or [p for p in default_trace_paths() if p.exists()]` pre-filters by existence, so load_events' `print(f"trace not found: {path}", file=sys.stderr)` can never fire on a default invocation. A user with no telemetry now gets only 'no events found' with no path named -- a small discoverability regression inside a change whose point is discoverability.
  Fix: Report the paths that were looked for when the result set is empty.

- **[Low] runs_dir() and event_path() are newly PUBLIC and enforce none of the invariants their docstring relies on**
  Evidence: kit_telemetry.py:341-344 -- `event_path(project, run_id)` interpolates run_id into a path with no whitelist check; the docstring defers to the caller ('run_id is whitelisted by _resolve_run_id before it ever reaches here'). True today (sole call site is line 483, after _resolve_run_id), but it is documentation, not enforcement, on a now-public API in a module another script has just started importing. event_path('/p', '../../../../tmp/pwned') returns a path resolving to /tmp/pwned.jsonl.
  Fix: Enforce _RUN_ID_RE inside event_path, or make both helpers private and export only RUNS_SUBDIR -- the single name trace_query actually consumes.

## Security Findings
_Source: security-review_

- **[High] FIXED IN REVIEW -- the aggregate readout that REPLACES the removed announcement could be forged by untrusted workspace input**
  Evidence: trace_query.print_summary interpolated session_id and event_type straight into stdout with no escaping, on a surface ISSUE-071 newly put on the default path. Reproduced through the REAL production emitter CLI (not a hand-planted file): `kit_telemetry.py --event $'benign\n  unattributed events: 0\nsession \x1b[32mALL-CLEAR\x1b[0m'` made `trace_query.py summary` render a fabricated clean block reading 'unattributed events: 0' while the TRUE unattributed count was 2, plus raw ESC (0x1b) bytes reaching the terminal. kit_telemetry._quote is this exact defence on the write side and its docstring names the threat verbatim ('cannot forge a second line that reads like an all-clear'); PR #141's review already had to extend it from one announcement site to all of them. This is review lesson 16 recurring on the new consumer. It matters more than a generic output bug because ISSUE-071's justification for deleting the per-emit stdout line is that this readout is the durable record.
  Fix: APPLIED: added trace_query._safe() (escapes only values carrying control characters, so ordinary output is unchanged) and routed session_id plus every Counter key through it via _join(). Post-fix the same input renders as ONE escaped token on a single line, no raw ESC, and only the true count. Pinned in BOTH directions by tests/test_run_telemetry.py::test_a_planted_value_cannot_forge_a_summary_line and ::test_an_ordinary_value_is_not_mangled; both assertions verified load-bearing by mutation (pass-through _safe and always-repr _safe each kill their test).

- **[Medium] FIXED IN REVIEW -- one planted non-object JSON line made the entire durable record unreadable**
  Evidence: load_events caught only json.JSONDecodeError, so a line that is valid JSON but not an object ('123', '"x"', 'null', '[]', 'true') was collected and summarize() then called .get on it: AttributeError: 'int' object has no attribute 'get'. Newly reachable because this PR put .claude/runs/*.jsonl on the default path via a glob -- verified by differential probe: on main the identical plant is ignored (clean exit 0), on the branch it crashes. One byte in a workspace file blinded the readout this PR substitutes for the removed announcement.
  Fix: APPLIED: load_events now appends only dict values, at the same site that already tolerates a torn line. Pinned both directions (::test_a_non_object_json_line_is_skipped_not_fatal and ::test_ordinary_event_lines_are_still_collected); both verified load-bearing by mutation.

- **[Medium] NOT FIXED -- the new read path has none of the write path's node/symlink/containment hardening (review lesson 5)**
  Evidence: Reproduced against the post-fix tree, each in its own fixture with a bounded timeout. (a) A FIFO named *.jsonl in .claude/runs/ makes path.read_text() block forever -- HANG, no exit within 15s. kit_telemetry added O_NONBLOCK for exactly this and its docstring (:76-82) explains that a hang stalls a caller instead of failing it. (b) A *.jsonl symlink pointing outside the project is followed and its content reaches stdout; .claude/runs itself as a symlinked directory is also followed -- the write side refuses both via O_NOFOLLOW and the second containment leg. (c) A directory named *.jsonl crashes with IsADirectoryError. (d) A *.jsonl symlinked to /dev/zero reads unbounded into memory (read_text slurps the whole file; no size cap, while the write side caps events at 4096 bytes). (e) Filenames are not filtered by _RUN_ID_RE, so any planted name is in scope. Differential probe confirms (a) and (c) are NEWLY reachable on the default path -- main ignores the same plants. Calibration: nothing auto-invokes trace_query.py (grepped the whole repo -- no hook, gate or shell script calls it), so a hang wedges a developer's terminal rather than stalling a gate; that is why this is Medium and not High.
  Fix: Apply the pattern kit_telemetry already establishes 20 lines away: os.open(path, O_RDONLY|O_NOFOLLOW|O_NONBLOCK) + fstat/S_ISREG rejection + streaming line reads with a byte budget, plus resolve()/is_relative_to() containment on the glob and an _RUN_ID_RE filename filter. One change closes (a)-(e). Needs a carrier.

- **[Medium] NOT FIXED -- _parse_ts catches only ValueError, so a planted timestamp crashes the reader**
  Evidence: Reproduced post-fix. (a) A non-string ts: datetime.strptime(12345, ...) raises TypeError, which `except ValueError` misses -- and the PR's NEW fromisoformat fallback repeats the same narrow catch. Crash: TypeError: strptime() argument 1 must be str, not int. (b) A bucket mixing naive and aware timestamps raises TypeError: can't compare offset-naive and offset-aware datetimes at the first_ts/last_ts comparison. I checked whether (b) is reachable from legitimate data and it is NOT: agent_state.py stamps time.strftime('%Y-%m-%dT%H:%M:%S%z') (aware) and the emitter stamps datetime.now(timezone.utc).isoformat() (aware), and the two streams land in different session buckets anyway. Both are therefore attacker-plantable only -- reported at Medium rather than High on that basis.
  Fix: Catch (ValueError, TypeError) in both legs of _parse_ts, and normalise to a single tz convention (or skip the min/max update) when a parsed stamp's awareness differs from the bucket's. Needs a carrier.

## Over-Engineering

- **[Low] [yagni] trace_query's per-event_type `script_events` breakdown is not asked for by any AC**
  Evidence: AC-4 asks only that a named kit script read the stream on a default path and that a test pin the written path == the read path. The `unattributed events` count is justified -- AC-3's durable-record argument leans on it. The `script_events` Counter, its dict entry, and its print_summary line (summarize:126, out dict:150, print_summary:170) are an additional readout no AC requests: about 6 lines. Review lesson 14 predicts exactly this -- ISSUE-071 is a DECISION request, and that is where unrequested surface ships. Notably it is also one of the two values that carried the forging vector fixed above.
  Fix: Keep only `unattributed_events` unless a consumer for the breakdown is named, or record the breakdown as a deliberate extra in the PR body.

- **[Low] [shrink] two new public helpers where the consumer needs one constant**
  Evidence: runs_dir() and event_path() are both added to kit_telemetry's public surface, but trace_query imports only RUNS_SUBDIR. event_path() has one call site (line 483) and runs_dir() two. The AC-4 identity pin is carried entirely by the constant -- verified by mutation: re-typing the literal in the consumer kills the test, and moving the constant moves both ends.
  Fix: Make them private (_runs_dir / _event_path) or inline them; export only RUNS_SUBDIR. Also closes the unvalidated-public-API finding above.

- **[Low] [shrink] the README KIT_RUN_ID bullet grew from 6 lines to 14 for a one-line doc obligation**
  Evidence: Review lesson 2 asks for one line in the owning module docstring and one in the most relevant user-facing doc. The README bullet now restates the full unset/invalid split, the rationale, and the consumer invocation; docs/telemetry_schema.md separately gains a 13-line 'Announcement scarcity' paragraph saying much of the same. Not wrong -- the module docstring and both docs are accurate and consistent -- but it is roughly 3x the obligation, and the duplication is itself drift surface.
  Fix: Advisory only. Consider pointing the README bullet at docs/telemetry_schema.md rather than restating the rationale in both.
