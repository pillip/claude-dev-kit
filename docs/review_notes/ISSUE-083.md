- **[Low] A `git branch --track` failure inside resolve_from_remote exits non-zero with no named reason= line**
  Evidence: scripts/worktree.sh:193 `git branch --quiet --track "$branch" "origin/$branch" >&2` is the function's last statement, and resolve_from_remote is invoked as `resolve_from_remote "$branch" || return 1` (line 250) — a `||` context, which suppresses `set -e` inside the callee. A failure there therefore propagates as a bare non-zero return with none of the five `reason=` refusals printed, so AC-2's "stderr names the branch and the specific reason" degrades to whatever git itself writes. Unreachable in practice (the `has_local`/`has_remote_ref` probe immediately above has just established no local ref exists), and the fail-closed direction is preserved — stdout stays empty and nothing is created — so this is a message-quality gap, not a fail-open.
  Fix: Wrap the final branch creation the same way the two git consultations above it are wrapped: `rc=0; git branch --quiet --track ... || rc=$?` with a `refuse_create "$branch" "branch-create-failed" ...` on non-zero. Deferred — not worth a code change on an unreachable path during review.
