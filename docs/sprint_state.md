Findings, in the order they matter:

1. **A Task sub-agent CAN invoke skills.** The unrestricted sub-agent received a real `Skill` tool whose listing includes `code-review` and `security-review` — **bare, not `claude-dev-kit:`-namespaced**. SPEC-066's categorical conclusion ("no mechanism can make the primary path execute from the sub-task review context on today's runtime") is therefore **refuted, not merely confounded**: the capability exists at the runtime level and was absent only because the kit's own agent `tools:` allowlists omit it.
2. **The sub-agent's `tools:` allowlist wins over the skill's `allowed-tools`** — confirmed by the contrast between rows 1 and 2/3.
3. **The correct grant token is `Skill`, NOT `SlashCommand`.** `SlashCommand` does not exist as a tool in *any* probed sub-agent context on 2.1.224 — not loaded, not deferred. `skills/review/SKILL.md`'s existing `allowed-tools: … SlashCommand` is therefore not the usable mechanism from sub-task context (it may still be correct for the main-session path, which was not probed — do not overclaim). Granting `SlashCommand` on the review-path agents would reproduce exactly the ISSUE-072 defect it is meant to fix: a grant naming a tool nothing provisions.
4. **Counter-evidence that a grant can silently fail to materialise.** `Glob` and `Grep` are granted in BOTH kit agent definitions and were provisioned in NEITHER (independently observed in two separate contexts, one of them first-hand). So "granted" does not imply "provisioned" on this runtime, and a `Skill` grant's materialisation is **UNVERIFIED** until re-probed. This is the ISSUE-014 rule earning its keep inside ISSUE-072 itself.
5. **The grant's live effect is NOT observable in this session**, and no amount of care inside the issue changes that: (a) the agent registry is frozen at session start — a project-level probe agent written to `.claude/agents/` mid-session was rejected with `Agent type not found`, so a `tools:` edit cannot take effect until a restart; and (b) the live kit agents are served from the **installed plugin cache at version 0.5.0** (`~/.claude/plugins/cache/claude-dev-kit/claude-dev-kit/0.5.0`, gitCommitSha 6140284), while this repo is at **0.7.0** — so an edit to `agents/reviewer.md` on main does not reach a running session at all until the plugin is updated. ISSUE-072's AC-2 ("evidenced by a live run recorded in the PR") is consequently **not satisfiable within this sprint**; it needs a post-restart, post-plugin-update re-probe, which requires its own durable carrier (review lesson 15) rather than a PR-body promise.
